# 风扇声音与省电

打开 PS5LM 就会听到风扇变大——即使一个模型都没载。这不是模型在算，是界面一直在画。

## 为什么没载模型也响

- 主循环的节拍由电视的垂直同步定住（`eglSwapInterval(1)`），所以它每秒跑 60 圈。这个设计
  对动画是对的，问题在于它不知道「画面没变」。
- 一圈就是一整屏：全屏渐变背景（每个像素跑一次片元着色器）、几千个 SDF 四边形、字形图集，
  然后 `eglSwapBuffers` 提交一次。
- 主页静止时这些内容每一帧都一模一样，但主循环照画、照提交。于是驱动每秒忙 60 次，SoC 一直
  在工作状态，风扇按它的曲线转起来。
- 载入模型之后更响是另一回事：那时 GPU 真的在算 token，这部分没有省的空间。

## 这一版做了什么

1. **给每帧算一个指纹。** 画完之后把所有四边形（`DrawList` 的实例）、按纹理和裁剪切出来的
   批次（run）、背景模式与颜色、是否需要磨砂玻璃，一起算成一个 64 位哈希（`frame_stamp`）。
   两份指纹相同，就是同一幅画面。
2. **指纹没变就不提交。** 不跑 `present`、不 `swap`——上一帧还在屏幕上，画面本来就一样。
   GPU 这时完全空闲。
3. **长时间静止降到半速。** 连续 30 帧没变之后，主循环从 60 Hz 降到 30 Hz，省掉剩下的 CPU；
   按任何键、或画面有任何变化，立刻回到 60 Hz。
4. **每两秒补一帧。** 静止 60 帧之后强制提交一次（心跳），不让显示管线长时间没人碰。
5. **每圈都按 1/60 秒节流。** 就算某台机器的 `eglSwapBuffers` 不阻塞，循环也不会空转。
6. **会动的页面照旧。** 背景里除了纯渐变以外每种模式都随时间变化（星场、极光、扫描线），
   指纹天然每帧不同，所以那些页面、以及载入中的进度条、忙碌页，仍然逐帧提交。

纯渐变背景是静态的，这正是本 app 用的那一种，所以主页、模型、API、设置这些页面在静止时
都可以被跳过去。

## 两个开关

写进 `/data/PS5LM/env.txt`，一行一个 `NAME=value`，改完重开 app：

| 行 | 默认 | 作用 |
|---|---|---|
| `PS5LM_FPS=30` | 60 | 帧率上限，10 到 60。30 让动画页面和载入中页面的功耗也降一半 |
| `PS5LM_STILL=0` | 开 | 关掉静止帧跳过，用来对比（排查画面不刷新时用） |

这些名字和 `RADV_`、`GGML_`、`LLAMA_` 开头的行一样由 app 自己读，日志里会回显。
启动时日志会有一行确认：

```
frame 60 fps at most, still frames presented once
```

## 怎么看效果

app.log 里每 600 帧（静止时约 20 秒）会有一行：

```
loop frames=600 mean=16.70ms max=17.10ms hist=0,598,2,0,0,0,0 draw 0.80 ms, swap 16.20 ms, presented 2, still 598
```

- `presented 2, still 598`：600 圈里只提交了 2 帧，其余 598 圈什么都没画——跳过生效了。
- `swap 16.20 ms`：一帧的等待来自垂直同步，说明 `eglSwapBuffers` 在阻塞（这是期望的行为）。
- `draw 0.80 ms`：CPU 侧记录一帧的成本，用来判断瓶颈在 CPU 还是 GPU。
- 如果 `presented` 一直是 600，说明当时那一页有东西每帧都在动（载入中、下载中、或控制台曲线
  正在刷新），那时跳过不会发生。

## 还没验证的部分

- 静态交叉编译和包内自检都过了，但功耗和噪音**没有在真机上量过**：这一版给的是机制和日志，
  降多少要靠听和看日志。
- 载入模型后的风扇声音不受影响，`PS5LM_FPS` 只作用于界面。
- 控制器输入的采样仍然是每圈一次；降到半速时，按键识别最多晚 33 毫秒。

如果风扇还是很大，把 `loop ...` 那几行和 `frame ... fps at most` 那行发出来：它们能说明当时
是「跳过了但还在响」（问题在别处）还是「根本没跳过」（那一页有东西在动）。
